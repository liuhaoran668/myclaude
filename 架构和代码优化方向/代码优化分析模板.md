# 第一部分：通用检查项

## 1.1 命名规范

### 规范对照表

| 类型 | C++ 风格 | Python 风格 |
|------|----------|-------------|
| 类名 | `PascalCase` | `PascalCase` |
| 函数名 | `snake_case` 或 `camelCase` | `snake_case` |
| 变量名 | `snake_case` | `snake_case` |
| 常量 | `kConstantName` 或 `UPPER_SNAKE` | `UPPER_SNAKE_CASE` |
| 私有成员 | `name_` (后缀下划线) | `_name` (前缀下划线) |
| 宏 | `UPPER_SNAKE_CASE` | N/A |

### 命名质量检查

| 问题 | 示例 | 改进 |
|------|------|------|
| **缩写不明** | `getMgr()` | `get_manager()` |
| **类型前缀** | `strName`, `intCount` | `name`, `count` |
| **无意义命名** | `data`, `info`, `temp` | 具体描述其内容 |
| **动词混乱** | `getData()` 却会修改状态 | `fetch_data()` 或拆分 |
| **bool 命名** | `flag`, `status` | `is_active`, `has_data` |

### 检查清单

- [ ] 命名是否反映用途而非类型？
- [ ] 缩写是否在团队内有共识？
- [ ] bool 变量是否用 `is_/has_/can_/should_` 前缀？
- [ ] 函数名是否是动词或动词短语？
- [ ] 类名是否是名词或名词短语？

## 1.2 函数设计

### 单一职责

```cpp
// ❌ 做太多事
void process_and_save_and_notify(Data data) {
    validate(data);
    transform(data);
    save_to_db(data);
    notify_subscribers(data);
}

// ✅ 拆分
void process(Data data) {
    validate(data);
    transform(data);
}
void save(Data data) { save_to_db(data); }
void notify(Data data) { notify_subscribers(data); }

// 编排层
void handle_data(Data data) {
    process(data);
    save(data);
    notify(data);
}
```

### 参数数量

| 参数数量 | 建议 |
|---------|------|
| 0-2 | ✅ 理想 |
| 3-4 | ⚠️ 考虑是否可以合并为结构体 |
| 5+ | ❌ 应该重构 |

```cpp
// ❌ 参数过多
void create_hand(string type, string interface, int baud,
                 int joints, bool auto_start, int timeout);

// ✅ 使用配置对象
struct HandConfig {
    string type;
    string interface;
    int baud_rate = 1000000;
    int joint_count = 6;
    bool auto_start = true;
    int timeout_ms = 5000;
};

void create_hand(const HandConfig& config);
```

### 返回值设计

| 场景 | C++ 推荐 | Python 推荐 |
|------|----------|-------------|
| 可能失败 | `std::optional<T>` / `expected<T,E>` | `Optional[T]` / 异常 |
| 多值返回 | 结构体 / `std::tuple` | `tuple` / `NamedTuple` / `dataclass` |
| 错误信息 | `expected<T, Error>` | 异常 + 异常类型 |
| 无返回值 | `void` | `None` |

### 检查清单

- [ ] 函数是否只做一件事？
- [ ] 函数长度是否 < 50 行？
- [ ] 参数数量是否 ≤ 4？
- [ ] 是否有 flag 参数？（应拆分为多个函数）
- [ ] 返回值是否清晰表达成功/失败？

## 1.3 错误处理

### 错误处理策略对比

| 策略 | 适用场景 | C++ | Python |
|------|----------|-----|--------|
| **异常** | 罕见错误、无法恢复 | `throw` | `raise` |
| **返回值** | 预期内的失败 | `optional` / `expected` | `Optional` |
| **断言** | 编程错误、永不发生 | `assert()` | `assert` |
| **日志** | 需要记录但不阻止执行 | spdlog | logging |

### 异常层次设计

```cpp
// C++ 异常层次
class HandError : public std::runtime_error {
    using runtime_error::runtime_error;
};

class ConnectionError : public HandError {
    using HandError::HandError;
};

class StateError : public HandError {
    using HandError::HandError;
};

class TimeoutError : public HandError {
    using HandError::HandError;
};
```

```python
# Python 异常层次
class HandError(Exception):
    """基础异常"""
    pass

class ConnectionError(HandError):
    """连接错误"""
    pass

class StateError(HandError):
    """状态错误"""
    pass

class TimeoutError(HandError):
    """超时错误"""
    pass
```

### 常见问题

| 问题 | 示例 | 改进 |
|------|------|------|
| **吞掉异常** | `catch(...) {}` | 至少记录日志 |
| **异常太宽泛** | `catch(exception&)` 处理所有 | 分类处理 |
| **错误码魔数** | `return -1;` | 返回枚举或 `expected` |
| **无异常说明** | 函数可能抛什么不清楚 | 文档注明 |

### 检查清单

- [ ] 是否有裸的 `catch(...)` 或 `except:`？
- [ ] 异常是否有层次结构？
- [ ] 错误信息是否包含上下文？
- [ ] 是否使用异常链（`raise from` / `std::throw_with_nested`）？
- [ ] 析构函数/finally 是否避免抛出异常？

## 1.4 注释与文档

### 注释类型

| 类型 | 何时使用 | 示例 |
|------|----------|------|
| **API 文档** | 公共接口 | Doxygen / docstring |
| **实现注释** | 复杂算法、非显而易见的逻辑 | `// 使用 X 算法因为...` |
| **TODO** | 待办事项 | `// TODO(author): 描述` |
| **WARNING** | 危险操作 | `// WARNING: 不要在锁内调用` |

### 代码文档模板

**C++ (Doxygen)**：
```cpp
/**
 * @brief 设置目标角度
 *
 * 异步设置各关节目标角度，实际运动由硬件控制。
 *
 * @param angles 目标角度列表，长度必须等于关节数
 * @param speed 运动速度因子，范围 [0.1, 2.0]，默认 1.0
 * @return true 命令已发送
 * @return false 发送失败（连接断开等）
 *
 * @throws StateError 设备未启动或已关闭
 * @throws ValueError 角度列表长度不正确或速度超出范围
 *
 * @note 线程安全
 * @warning 快速连续调用可能导致运动不平滑
 *
 * @code
 * hand.set_angle({0, 30, 60, 90, 120, 150});
 * hand.set_angle({0, 0, 0, 0, 0, 0}, 0.5);  // 慢速复位
 * @endcode
 */
bool set_angle(const std::vector<float>& angles, float speed = 1.0f);
```

**Python (docstring)**：
```python
def set_angle(
    self,
    angles: List[float],
```

## 2.1 内存与资源管理

### 智能指针使用指南

| 类型 | 语义 | 使用场景 |
|------|------|----------|
| `unique_ptr` | 独占所有权 | 工厂创建、成员变量 |
| `shared_ptr` | 共享所有权 | 需要多处持有 |
| `weak_ptr` | 观察者 | 打破循环引用、可选引用 |
| 裸指针 | 不拥有 | 参数传递、返回内部引用 |

```cpp
// ✅ 正确使用
class Hand {
    unique_ptr<Driver> driver_;        // Hand 独占 Driver
    shared_ptr<Config> config_;        // 配置可能被多处共享
    vector<weak_ptr<Observer>> obs_;   // 观察者弱引用，防止循环

public:
    Driver* get_driver() { return driver_.get(); }  // 返回裸指针，不转移所有权
};
```

### RAII 模式

```cpp
// 资源获取即初始化
class SocketGuard {
    int fd_;
public:
    explicit SocketGuard(int fd) : fd_(fd) {}
    ~SocketGuard() { if (fd_ >= 0) ::close(fd_); }

    // 禁止拷贝
    SocketGuard(const SocketGuard&) = delete;
    SocketGuard& operator=(const SocketGuard&) = delete;

    // 允许移动
    SocketGuard(SocketGuard&& other) noexcept : fd_(other.fd_) {
        other.fd_ = -1;
    }
};
```

## 2.2 const 正确性

### const 使用位置

```cpp

    // 1. const 成员函数：不修改对象状态
```

## 2.4 C++ 并发

### 锁的选择

| 锁类型 | 使用场景 |
|--------|----------|
| `mutex` | 一般互斥 |
| `recursive_mutex` | 同一线程可能多次加锁（应避免） |
| `shared_mutex` | 读多写少，读写锁 |
| `timed_mutex` | 需要超时的场景 |

### 锁的使用

```cpp
// ✅ 使用 RAII 锁
{
    lock_guard<mutex> lock(mtx_);
    // 临界区
}

// ✅ 需要解锁控制时用 unique_lock
{
    unique_lock<mutex> lock(mtx_);
    // ...
    lock.unlock();  // 提前解锁
    // 非临界区操作
}

// ✅ 读写锁
{
    shared_lock<shared_mutex> lock(mtx_);  // 读锁
    // 读取操作
}
{
    unique_lock<shared_mutex> lock(mtx_);  // 写锁
    // 写入操作
}
```

### 原子操作

```cpp
// 简单计数器
atomic<int> counter{0};
counter.fetch_add(1, memory_order_relaxed);

// 状态标记
atomic<bool> running{true};
running.store(false, memory_order_release);
if (running.load(memory_order_acquire)) { ... }

// CAS 操作
atomic<State> state{State::CREATED};
State expected = State::CREATED;
if (state.compare_exchange_strong(expected, State::RUNNING)) {
    // 成功转换状态
}
```

- [ ] 是否使用 RAII 锁（`lock_guard`/`unique_lock`）？
- [ ] 是否避免在持锁时调用用户代码？
- [ ] 多个锁是否有固定的加锁顺序？
- [ ] 原子操作的内存序是否正确？

## 3.2 Python 惯用法

### 列表推导 vs 循环

```python
# ✅ 简单转换用列表推导
squares = [x**2 for x in range(10)]
filtered = [x for x in items if x > 0]

# ❌ 复杂逻辑不要硬塞进推导式
# 难以阅读
result = [
    process(x) if x > 0 else default
    for x in items
    if validate(x) and check(x)
]

# ✅ 复杂逻辑用循环
result = []
for x in items:
    if not (validate(x) and check(x)):
        continue
    value = process(x) if x > 0 else default
    result.append(value)
```

### 上下文管理器

```python
# ✅ 文件操作
with open("file.txt") as f:
    data = f.read()

# ✅ 自定义上下文管理器
from contextlib import contextmanager

@contextmanager
def timing(name: str):
    start = time.time()
    try:
        yield
    finally:
        print(f"{name} took {time.time() - start:.2f}s")

with timing("operation"):
    do_something()
```

### 线程安全

```python
import threading
from queue import Queue

class SafeCounter:
    def __init__(self):
        self._value = 0
        self._lock = threading.Lock()

    def increment(self):
        with self._lock:
            self._value += 1

    def get(self) -> int:
        with self._lock:
            return self._value

# 线程安全队列
queue: Queue[Data] = Queue()
queue.put(data)
data = queue.get(timeout=5.0)
```

```python
# ✅ 阻塞操作放到线程池
async def run_blocking():
    loop = asyncio.get_event_loop()
```

## 4.2 常见性能问题

### 算法复杂度

| 问题 | 示例 | 改进 |
|------|------|------|
| O(n²) 查找 | 嵌套循环查找 | 使用 set/dict O(1) |
| 重复计算 | 循环内重复调用函数 | 缓存结果 |
| 不必要拷贝 | 大对象值传递 | 引用/移动语义 |

### 内存分配

```cpp
// ❌ 循环内分配
for (int i = 0; i < n; ++i) {
    vector<int> temp;  // 每次分配
    temp.push_back(i);
}

// ✅ 预分配
vector<int> temp;
temp.reserve(n);
for (int i = 0; i < n; ++i) {
    temp.push_back(i);
}
```

```python
# ❌ 字符串拼接
result = ""
for s in strings:
    result += s  # O(n²)

# ✅ join
result = "".join(strings)  # O(n)
```

# 附录：代码异味速查

| 异味 | 描述 | 重构方向 |
|------|------|----------|
| **长方法** | > 50 行 | 提取方法 |
| **长参数列表** | > 4 个参数 | 引入参数对象 |
| **重复代码** | 相似代码块 | 提取方法/模板 |
| **发散式变化** | 一个类因多种原因修改 | 拆分类 |
| **霰弹式修改** | 一个变化影响多个类 | 内联/移动方法 |
| **特性依恋** | 方法更多使用其他类数据 | 移动方法 |
| **数据泥团** | 一组数据总是一起出现 | 提取类 |
| **基本类型偏执** | 使用基本类型代替小对象 | 引入值对象 |
| **switch 语句** | 多处相同 switch | 多态替换 |
| **平行继承体系** | 新建一个子类必须新建另一个 | 合并继承体系 |
| **冗余类** | 类几乎不做事 | 内联类 |
| **过度设计** | 不需要的通用性 | 简化 |
| **临时字段** | 字段仅在特定情况使用 | 提取类 |
| **消息链** | `a.b().c().d()` | 隐藏委托 |
| **中间人** | 类大多数方法委托给另一个类 | 移除中间人 |
| **不恰当亲密** | 两个类过于了解彼此 | 移动方法/字段 |
| **异曲同工的类** | 不同类做相同的事 | 统一接口 |
| **不完美的库类** | 库类缺少需要的方法 | 扩展方法 |
| **纯数据类** | 类只有字段和 getter/setter | 移入行为 |
| **被拒绝的遗赠** | 子类不需要父类方法 | 组合替代继承 |
| **注释** | 过多注释解释糟糕代码 | 重构代码 |
