# 第一阶段：问题发掘

## 1.1 代码重复问题

### 检测方法

**C++ 项目**：
```bash
# 使用 CPD (Copy/Paste Detector)
pmd cpd --minimum-tokens 50 --files src/ --language cpp

# 使用 Simian
simian **/*.cpp **/*.h
```

**Python 项目**：
```bash
# 使用 pylint
pylint --disable=all --enable=duplicate-code src/

# 使用 radon
radon raw -s src/
```

### 常见重复模式

| 重复类型 | 表现 | 根因 | 解决方向 |
|---------|------|------|----------|
| **逻辑重复** | 多个类有相似的处理流程 | 缺少抽象基类 | 模板方法 / CRTP |
| **数据重复** | 相同数据结构多处定义 | 缺少共享模块 | 数据类提取 |
| **配置重复** | 硬编码常量散落各处 | 缺少配置中心 | 配置对象 / 工厂 |
| **验证重复** | 相同校验逻辑多处出现 | 缺少验证层 | 装饰器 / 切面 |

### 实际案例

**问题**：LinkerHand 项目中 `L6AngleManager` 和 `L10AngleManager` 有 80% 相同代码

**分析**：
```cpp
// 重复部分
class L6AngleManager {
    void set_angle(vector<float> angles) {
        validate(angles);           // 相同
        auto frame = build_frame(); // 相同
        driver_->send(frame);       // 相同
    }
};

class L10AngleManager {
    void set_angle(vector<float> angles) {
        validate(angles);           // 相同
        auto frame = build_frame(); // 相同
        driver_->send(frame);       // 相同
    }
};

// 差异部分：关节数量、指令码
```

**解决方案**：CRTP 模板基类提取通用逻辑

```cpp
template<typename Derived>
class AngleManagerBase {
protected:
    void set_angle_impl(vector<float> angles) {
        validate(angles);
        auto frame = derived().build_frame(angles);  // 差异点由子类实现
        driver_->send(frame);
    }

    Derived& derived() { return static_cast<Derived&>(*this); }
};

class L6AngleManager : public AngleManagerBase<L6AngleManager> {
    friend class AngleManagerBase<L6AngleManager>;
    Frame build_frame(vector<float> angles) { /* L6 特有实现 */ }
};
```

### 检查清单

- [ ] 是否存在复制粘贴的代码块？
- [ ] 多个子类是否有相同的方法实现？
- [ ] 配置/常量是否散落在多处？
- [ ] 相同的 try-catch 模式是否重复？

## 1.2 耦合度问题

### 检测方法

**依赖方向检查**：
```
用户代码 → Facade → Manager → Driver → 硬件
   ↓         ↓         ↓         ↓
  高层      中间层    底层      最底层

✅ 正确：高层依赖低层
❌ 错误：低层依赖高层（循环依赖）
```

**耦合度指标**：
- **传入耦合 (Ca)**：有多少模块依赖此模块
- **传出耦合 (Ce)**：此模块依赖多少其他模块
- **不稳定度 I = Ce / (Ca + Ce)**：越接近 1 越不稳定

### 常见耦合问题

| 问题 | 表现 | 解决方向 |
|------|------|----------|
| **Facade 暴露内部** | `hand.angle_manager.xxx()` | 代理模式 / 私有化 |
| **Manager 互相调用** | `AngleManager` 直接调用 `TouchManager` | 事件总线 / 中介者 |
| **Driver 知道 Manager** | Driver 回调直接操作 Manager 状态 | 回调接口解耦 |
| **硬编码依赖** | `new CANDriver()` 在 Manager 内部 | 依赖注入 |

### 实际案例

**问题**：Facade 暴露 Manager，导致生命周期不一致

```cpp
// 用户代码
auto hand = make_shared<L6Hand>();
auto* manager = hand->get_angle_manager();  // 暴露内部

hand->close();  // Facade 关闭
manager->get_angle();  // ??? 应该发生什么？
```

**三种处理方式**：

| 方案 | 实现 | 优点 | 缺点 |
|------|------|------|------|
| **禁止暴露** | 删除 `get_xxx_manager()` | 封装彻底 | 高级用户不便 |
| **代理包装** | 返回受 Facade 控制的代理对象 | 可控 | 复杂度增加 |
| **状态检查** | Manager 内部检查 Facade 状态 | 兼容现有 | 强依赖 Facade |

**推荐方案**：状态检查 + 统一异常

```cpp
class AngleManager {
    weak_ptr<Hand> owner_;  // 弱引用 Facade

    void check_state() {
        if (auto owner = owner_.lock(); !owner || owner->is_closed()) {
            throw StateError("Hand is closed");
        }
    }

    vector<float> get_angle() {
        check_state();  // 每个 API 入口检查
        return do_get_angle();
    }
};
```

### 检查清单

- [ ] Facade 是否暴露内部对象？
- [ ] 暴露的对象是否受 Facade 生命周期控制？
- [ ] 模块间是否存在循环依赖？
- [ ] 依赖是注入还是内部硬编码？

## 1.3 生命周期契约问题

### 核心问题

```
创建 ───→ 运行 ───→ 停止 ───→ 关闭
 │         │         │         │
 └─────────┴─────────┴─────────┘
          每个状态下各 API 应该如何表现？
```

### 契约矩阵模板

| API | CREATED | RUNNING | STOPPING | CLOSED |
|-----|---------|---------|----------|--------|
| `start()` | ✅ → RUNNING | ❌ StateError | ❌ StateError | ❌ StateError |
| `stop()` | ⚠️ 幂等 | ✅ → STOPPING | ⚠️ 幂等 | ⚠️ 幂等 |
| `close()` | ✅ → CLOSED | ✅ stop+close | ✅ 等待+close | ⚠️ 幂等 |
| `get_data()` | ❌ StateError | ✅ | ❌ StateError | ❌ StateError |
| `set_data()` | ❌ StateError | ✅ | ❌ StateError | ❌ StateError |

### 常见问题

| 问题 | 风险 | 解决 |
|------|------|------|
| **close 非幂等** | 重复关闭崩溃 | 状态标记 + 早返回 |
| **close 后行为不一致** | 有的返回空，有的抛异常 | 统一策略 |
| **关闭顺序错误** | 先停消费者再停生产者，导致数据丢失 | 依赖拓扑排序 |
| **析构不调 close** | 资源泄露 | 析构函数调用 close |

### 实际案例

**问题**：close 后各 API 行为不一致

```cpp
// 修复前
hand->close();
hand->get_angle();  // L6: 返回空 vector
                    // L10: 抛出 runtime_error
                    // O6: 直接崩溃（空指针）
```

**解决方案**：统一状态检查

```cpp
// 修复后：所有 API 统一行为
class Hand {
    atomic<State> state_{State::CREATED};

    void ensure_running() {
        auto s = state_.load();
        if (s != State::RUNNING) {
            throw StateError(format("Invalid state: {}", to_string(s)));
        }
    }

    vector<float> get_angle() {
        ensure_running();  // 统一入口检查
        return angle_manager_->get_angle();
    }
};
```

### 检查清单

- [ ] 是否有明确的状态枚举？
- [ ] 状态转换是否有验证？
- [ ] close/stop 是否幂等？
- [ ] close 后各 API 行为是否一致？
- [ ] 关闭顺序是否正确（先生产者后消费者）？
- [ ] 析构函数是否调用 close？

### 回调阻塞问题（重点）

**问题场景**：

```cpp
// 危险代码
class Observable {
    mutex mtx_;
    vector<Callback> callbacks_;

    void notify(Data data) {
        lock_guard lock(mtx_);
        for (auto& cb : callbacks_) {
            cb(data);  // 🔥 持锁调用用户回调
                       // 如果回调耗时/阻塞，其他订阅者全部等待
                       // 如果回调内调用 subscribe/unsubscribe，死锁
        }
    }
};
```

**解决方案演进**：

```cpp
// 方案1：复制后锁外调用
void notify(Data data) {
    vector<Callback> cbs_copy;
    {
        lock_guard lock(mtx_);
        cbs_copy = callbacks_;  // 复制
    }
    for (auto& cb : cbs_copy) {
        cb(data);  // 锁外调用
    }
}

// 方案2：异步派发（推荐）
void notify(Data data) {
    vector<Callback> cbs_copy;
    {
        lock_guard lock(mtx_);
        cbs_copy = callbacks_;
    }
    for (auto& cb : cbs_copy) {
        thread_pool_.submit([cb, data] { cb(data); });  // 异步执行
    }
}

// 方案3：每个订阅者独立队列
class Subscriber {
    BlockingQueue<Data> queue_;
    thread worker_;

    Subscriber(Callback cb) {
        worker_ = thread([this, cb] {
            while (auto data = queue_.pop()) {
                cb(*data);
            }
        });
    }
};
```

### 检查清单

- [ ] 共享状态是否有锁保护？
- [ ] 是否存在持锁调用用户回调？
- [ ] 回调是否可能阻塞？
- [ ] 取消订阅时是否等待 in-flight 回调？
- [ ] close 和 业务操作 是否有并发处理？
- [ ] 析构时是否确保线程已退出？

# 第二阶段：方案设计

## 2.1 设计模式适配

### 问题 → 模式映射

| 问题 | 推荐模式 | C++ 实现 | Python 实现 |
|------|----------|----------|-------------|
| 代码重复（相同流程） | **模板方法 / CRTP** | CRTP 基类 | ABC + 抽象方法 |
| 代码重复（相同数据） | **数据类提取** | struct | dataclass |
| 对象创建复杂 | **工厂 / 建造者** | 工厂方法 + Builder | `@classmethod` |
| 接口简化 | **Facade** | 组合 + 转发 | 组合 + 转发 |
| 事件通知 | **观察者** | 回调列表 | 回调列表 / Signal |
| 状态复杂 | **状态机** | 状态枚举 + switch | 状态类 / Enum |
| 多种算法 | **策略** | 函数指针/std::function | 函数参数 |
| 资源管理 | **RAII** | 智能指针 + 析构 | 上下文管理器 |
| 解耦依赖 | **依赖注入** | 构造函数注入 | 构造函数注入 |

### CRTP 使用指南

**适用场景**：
- ✅ 多个子类有相同的算法框架，差异在个别步骤
- ✅ 需要编译期多态（避免虚函数开销）
- ✅ 子类数量相对固定

**不适用场景**：
- ❌ 需要运行时多态（根据条件选择实现）
- ❌ 子类差异过大（超过 50% 代码不同）
- ❌ 有复杂的多帧组装等特殊逻辑

**模板结构**：

```cpp
template<typename Derived>
class ManagerBase {
public:
    // 公共接口
    Result do_operation() {
        pre_operation();                    // 通用前置
        auto result = derived().impl();     // 子类实现
        post_operation();                   // 通用后置
        return result;
    }

protected:
    Derived& derived() { return static_cast<Derived&>(*this); }
    const Derived& derived() const { return static_cast<const Derived&>(*this); }

    // 可选钩子（有默认实现）
    void pre_operation() {}
    void post_operation() {}
};

class ConcreteManager : public ManagerBase<ConcreteManager> {
    friend class ManagerBase<ConcreteManager>;

    Result impl() {
        // 具体实现
    }
};
```

## 2.2 优先级排序

### 风险-收益矩阵

```
              高收益
                │
    ┌───────────┼───────────┐
    │   优先级1  │   优先级2  │
    │  高风险高收益│  低风险高收益 │
    │  谨慎执行   │  立即执行    │
────┼───────────┼───────────┼──── 低风险
    │   优先级4  │   优先级3  │    高风险
    │  高风险低收益│  低风险低收益 │
    │  考虑放弃   │  有空再做    │
    └───────────┼───────────┘
                │
              低收益
```

### 优化优先级建议

| 优先级 | 类别 | 示例 |
|--------|------|------|
| **P0 - 阻塞** | 会导致崩溃/数据损坏 | 并发数据竞争、资源泄露 |
| **P1 - 严重** | 行为不一致/难以维护 | 生命周期契约缺失、close 后行为不一 |
| **P2 - 重要** | 影响扩展/可维护性 | 代码重复、耦合过高 |
| **P3 - 改进** | 提升代码质量 | 命名规范、文档补充 |

# 附录：常用优化模式速查

## A. 代码重复 → CRTP/模板方法

```cpp
// Before: 重复代码
class A { void process() { validate(); doA(); send(); } };
class B { void process() { validate(); doB(); send(); } };

// After: CRTP
template<typename D> class Base {
    void process() { validate(); derived().doImpl(); send(); }
};
class A : Base<A> { void doImpl() { doA(); } };
class B : Base<B> { void doImpl() { doB(); } };
```

## B. 生命周期 → 状态机

```cpp
// Before: 无状态检查
void close() { cleanup(); }
void get() { return data_; }  // close 后也能调用

// After: 状态机
enum class State { CREATED, RUNNING, CLOSED };
atomic<State> state_{State::CREATED};

void close() {
    auto expected = State::RUNNING;
    if (!state_.compare_exchange_strong(expected, State::CLOSED)) {
        return;  // 幂等
    }
    cleanup();
}

void get() {
    if (state_ != State::RUNNING) throw StateError();
    return data_;
}
```

## C. 回调阻塞 → 异步派发

```cpp
// Before: 同步回调
void notify(Data d) {
    lock_guard lk(mtx_);
    for (auto& cb : callbacks_) cb(d);  // 阻塞
}

// After: 异步派发
void notify(Data d) {
    vector<Callback> cbs;
    { lock_guard lk(mtx_); cbs = callbacks_; }
    for (auto& cb : cbs) {
        executor_.submit([cb, d] { cb(d); });
    }
}
```

## D. Facade 暴露 → 状态检查

```cpp
// Before: 暴露后无保护
class Hand {
    AngleManager* get_angle_manager() { return &angle_mgr_; }
};
// hand->close() 后 manager 仍可调用

// After: 弱引用检查
class AngleManager {
    weak_ptr<Hand> owner_;
    void check() {
        if (auto o = owner_.lock(); !o || o->is_closed())
            throw StateError();
    }
    void get() { check(); /* ... */ }
};
```
